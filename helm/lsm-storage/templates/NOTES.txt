A Secret named {{ include "lsm-storage.fullname" . }}-auth was created with
PLACEHOLDER credentials. You MUST replace them before using this deployment:

  Option A — patch the existing Secret:
    kubectl create secret generic {{ include "lsm-storage.fullname" . }}-auth \
      --from-literal=API_TOKEN=<your-strong-token> \
      --from-literal=METRICS_TOKEN=<your-metrics-token> \

  Option B — use an externally managed Secret (recommended):
    kubectl create secret generic my-lsm-secrets \
      --from-literal=API_TOKEN=<your-strong-token> \
      --from-literal=METRICS_TOKEN=<your-metrics-token> \
      --from-literal=BFF_BASIC_AUTH=user:password

    helm upgrade {{ .Release.Name }} ./helm/lsm-storage \
      --set auth.existingSecret=my-lsm-secrets

=============================================================================
Enabling TLS (Backend)
=============================================================================

Create a TLS Secret (or use cert-manager) and then upgrade the release:

  kubectl create secret tls lsm-tls \
    --cert=path/to/tls.crt \
    --key=path/to/tls.key

  helm upgrade {{ .Release.Name }} ./helm/lsm-storage \
    --set tls.enabled=true \
    --set tls.certSecretName=lsm-tls

=============================================================================
Enabling Prometheus Monitoring
=============================================================================

If you have the Prometheus Operator installed:

  helm upgrade {{ .Release.Name }} ./helm/lsm-storage \
    --set metrics.serviceMonitor.enabled=true \
    --set metrics.serviceMonitor.additionalLabels.release=prometheus

The ServiceMonitor will use METRICS_TOKEN from the auth Secret as a bearer
token for authenticated scraping.
